- **2026-10-27 — Strands Agents SDK *local* session-storage pair, GHSA-3w55-933p-8pv5 (CVSS 7.1) + GHSA-763v-5pjm-fx36 (no score assigned; strands-agents < 1.48.0, fixed 1.48.0; REVIEWED tier — first reviewed-tier advisories on this SDK, published 2026-10-27T15:34Z via advisory sweep-73, no AWS bulletin yet; index still 2026-151-AWS at check time):** (a) `FileSessionManager` defaults to `/tmp/strands/sessions/` (world-writable) with predictable paths and a write pattern (`open(path+".tmp","w")` → `os.replace()`) that **follows symlinks** — a local attacker pre-placing a symlink at the `.tmp` path achieves **arbitrary file overwrite or injection of malicious session data for persistent prompt injection** (no HMAC/signature on session files — tampered data loads as-is); (b) same default storage is **world-readable under common umask 022** (dirs 0755, JSON 0644) on shared dev machines/CI hosts/notebooks/jump boxes/multi-user GPU servers, exposing persisted prompts, model output, tool inputs/outputs, and secrets passing through the agent. **Hunting read: the Strands lane produces again (third AWS-Distributed-SDK advisory cluster after the 2026-146 A2A cross-tenant leak) but this time the impact class is local-filesystem trust — the durable lesson is that agent *session persistence* is a secret-bearing artifact deserving the same containment scrutiny as the agent runtime itself. Portable probe battery: (1) for any agent/LLM framework writing conversation state to a shared temp path, check dir/file modes and symlink-following in the write pattern, (2) check whether persisted session content is later loaded as trusted input (tampered session → persistent prompt injection is the escalation from local-write to remote-behavior), (3) on shared GPU/CI hosts, enumerate readable agent-session dirs under /tmp for other users' prompts/tool-output secrets. The tamper→persistent-injection chain is the reportable twist: a local-write primitive converts to model-behavior control without any network access.** Source: https://github.com/advisories/GHSA-3w55-933p-8pv5

- **2026-10-27 — Apache Airflow *SSH provider* remote-command injection, GHSA-v5m9-m7pg-q8f3 / CVE-2026-111422 (apache-airflow-providers-ssh < 7.0.1, fixed 7.0.1; caught in advisory sweep-71, unreviewed tier, no CVSS assigned at check time, published 2026-10-27T00:32:50Z):** `SSHRemoteJobOperator` quotes the values of its templated `environment` parameter **only once**, although they are placed inside an **already-quoted wrapper script** — so shell syntax such as `$(...)` in a value executes on the remote SSH host. In a DAG that passes trigger-time input (`params` / `dag_run.conf`) into `environment`, **a user who can trigger the DAG but cannot author DAGs runs arbitrary commands on the remote host as the SSH connection's user**. Fix: upgrade providers-ssh to 7.0.1+. **Hunting read: double-quote-context escaping failure — the generator assumes single-quote sufficiency while embedding values in an outer quoted wrapper; same generator-injection lineage as 2026-145-AWS SAM CLI Makefile interpolation and 2026-151-AWS redshift-alpha SQL interpolation (third in the IaC/task-generator lane). The privilege delta is the payload: DAG-trigger (low trust) → remote-host RCE under a service SSH identity (high trust). Standing probe battery for any task/operator that renders templates into a shell command or wrapper script: (1) trace every quoting layer from template value to final shell — single-quote-then-embedded-in-quotes is breakable by `$(...)`/backticks, (2) enumerate which trigger-time inputs (params, conf, macros) reach the rendered command, (3) who holds trigger-only rights. Note: Apache project, not AWS-distributed software — VRP relevance via the AWS-integration surface, consistent with the 2026-10-20 providers-amazon SAML entry; both Airflow provider advisories in one week marks airflow provider-plugins as an active disclosure cluster.** Source: https://github.com/advisories/GHSA-v5m9-m7pg-q8f3
